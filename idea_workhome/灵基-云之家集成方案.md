# 灵基 × 云之家集成方案

> 版本：v1.0  
> 日期：2025-07  
> 涉及系统：灵基平台、云之家 

---

## 一、用户同步方案

### 1.1 场景一：云之家侧已有组织架构

**流程**：灵基侧主动拉取云之家组织架构，在灵基侧以云之家组织架构为主，并建立映射关系。

```
灵基平台
  │
  ├─ 1. 调用 openapi → 查询团队信息 → 获取 eid
  ├─ 2. 调用 openapi → 查询部门列表 → 获取 orgId
  ├─ 3. 调用 openapi → 查询用户列表 → 获取 openId
  └─ 4. 本地存储映射关系（eid / orgId / openId）
```

**映射关系存储结构：**

| 映射类型 | 灵基侧字段 | 云之家侧字段 | 说明 |
|---------|-----------|------------|------|
| 团队映射 | tenantId | eid | 企业/团队唯一标识 |
| 部门映射 | deptId | orgId | 组织部门唯一标识 |
| 用户映射 | userId | openId（内部字段 oid） | 用户唯一标识，外部统一叫 openId |

---

### 2.2 场景二：云之家侧无组织架构

**流程**：灵基侧将自身组织架构写入云之家，再建立映射关系。

```
灵基平台
  │
  ├─ 1. 调用 yzj-api → 创建云之家团队 → 返回 eid
  ├─ 2. 调用 yzj-api → 同步部门信息  → 返回 orgId
  ├─ 3. 调用 yzj-api → 同步用户信息  → 返回 openId
  └─ 4. 本地存储映射关系（eid / orgId / openId）
```

## 三、单点登录方案（SSO）

灵基客户端内嵌云之家日历、会议、知识库三个小程序模块，打开前需完成身份透传。

**核心流程：**

```
用户点击「日历/会议/知识库」
  │
  ├─ 1. 灵基客户端 → 灵基后端：请求获取 yzj ticket
  │       入参：当前用户 userId（灵基侧）
  │
  ├─ 2. 灵基后端 → 映射关系表：userId → openId（云之家侧）
  │
  ├─ 3. 灵基后端 → 云之家 openapi：用 openId + eid 换取 ticket
  │       接口：POST /rest/api/ticket/acquirebysessionid
  │
  ├─ 4. 云之家 openapi 内部：openId → personId（内部转换）
  │       调用 openorg: /contacts/getpersonidsbyopenids
  │       用 personId 生成 ticket 存入 Redis
  │
  ├─ 5. 灵基后端 → 灵基客户端：返回 ticket
  │
  └─ 6. 灵基客户端 → 云之家小程序：携带 ticket 打开，完成 SSO
```

> **说明**：云之家小程序支持 ticket 鉴权，ticket 有效期 1 小时，存储在 Redis 中。  
> ticket 内部绑定的是 personId，但对外接口入参接受 openId（oid），内部自动完成 openId → personId 的转换。

### 4.3 单点登录接口

#### 接口 C2：通过 openId 获取 ticket（新增对外接口，推荐方案）

> https://open.yunzhijia.com/rest/api/ticket/acquirebysessionid
> 
> 当前 `acquirebysessionid` 接口设计上依赖 access_token（用户登录态），不完全适合服务端 S2S 调用场景。建议新增一个纯服务端接口，入参为 openId + eid，直接返回 ticket。

- **状态**：⚠️ **待开发**
- **建议接口路径**：`POST https://open.yunzhijia.com/rest/api/ticket/getticketbyopenid`
- **系统**：openapi（外部 nginx）

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| eid | String | ✅ | 团队 ID |
| openId | String | ✅ | 用户 openId（即 oid） |
| appId | String | ✅ | 目标应用 ID |

**鉴权**：OAuth 1.0 签名（consumer_key + consumer_secret，无需 access_token）

**返回结果：**

```json
{
  "success": true,
  "data": {
    "ticket": "TICKET_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "expireIn": 3600
  }
}
```

**内部实现逻辑：**

```
1. 验证 OAuth 签名（consumer_key 鉴权）
2. 调用 openorg /contacts/getpersonidsbyopenids，openId → personId
3. 调用 ticket-service.generateAppTicket(personId, appId)
4. 返回 ticket
```
